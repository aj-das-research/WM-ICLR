# Registered matched horizon-ten training control

This is an ordinary training/evaluation horizon-mismatch control, not a new architecture or a novelty claim. Freeze this protocol, source hashes, all twelve configurations and original h5 evidence before any scientific run in the new namespace. Preserve every original result and checkpoint.

## Fixed campaign

- Four unchanged modes: Framewise, constant dynamics, ShiftWM (ours; factorized), and action-free. Seeds 0, 1, 2; twelve runs; every run completes all 30 epochs.
- Reuse the exact original `RealVideoWorldModel` and pinned LeWM implementation: width 192, depth 4, context width 32, context hidden 128, three observed support frames. No architecture or loss regularizer changes.
- Three observed support frames, their two executed action blocks, ten future action blocks, and ten future feature targets. Rollouts recurse on their own predictions; query images never condition predictions or inferred contexts. No teacher forcing.
- Original training split only; original validation split only for checkpoint selection and development evaluation. Exterior camera one. DINO cache, five-original-frame sampling cadence, action blocks, train-only normalization, training stride 2 and validation stride 5 are unchanged. Shared normalization is independently checked over all train episodes, including frames not eligible as h10 windows. Test and fresh-test payloads are never opened.
- AdamW lr 1e-4, weight decay .01, cosine decay to 1e-6, batch 128, gradient clipping 1, training BF16 on GPU; exactly the original settings. GPU jobs request one GPU each, eight CPUs and 40 GB memory. Three seed groups run four modes sequentially, at most two ws-ia GPUs and one gpu-partition GPU, after successful original generalization finalization.
- Training averages fixed-coordinate standardized MSE over all ten recursively predicted targets, features and sampled windows. Validation disables autocast and TF32, explicitly uses FP32 predicted/target tensors and preserves the original window-weighted mean over all targets/features, extending the target count from five to ten. An auxiliary equal-episode error is journaled for diagnosis but never selects a checkpoint. Reported evaluation remains equal-episode as in the original evaluator. Strictly lower validation error selects a checkpoint; ties select the earliest epoch.
- Resume only from an atomic completed-epoch package with optimizer, scheduler, loader generator and Python/NumPy/Torch RNG states. Partial epochs replay from the previous completed epoch. Distinct package kind `shiftwm_real_video_droid_horizon10_v1`; tensor-only offline reload checks normalization, architecture, parameter counts, exact metadata/source identity and SHA-256 manifests.

## Prespecified evaluations and decisions

Every selected new checkpoint receives standard h5 and h10 evaluation on their corresponding complete-window validation populations (24 evaluations). Preserve mean-all-query and endpoint errors, every mode/seed and unfavorable results. Compare ours against equally h10-trained Framewise with paired recording-session and training-seed bootstrap intervals, 10,000 draws, fixed seed 5198010. The all-ten mean metric is the primary control diagnostic; the tenth endpoint and h5 results are secondary.

For training-horizon comparisons, evaluate the original h5 checkpoint and new h10 checkpoint on exactly the same h10-eligible episode IDs, session IDs and query-start windows. Evaluate the h5 prefix of those exact windows for both checkpoints, and all ten steps for both; compare corresponding query endpoints. This adds 36 matched diagnostic evaluations beyond the 24 standard evaluations. Pairing rejects any mismatch in episodes, sessions or window starts. Standard full-population h5/h10 tables may differ in eligibility and are labeled accordingly.

Original h5 packages were selected using window-weighted all-five validation error; these new packages preserve window weighting and use all-ten error. Training and matching selection horizons change together as the intended horizon-control treatment. No new weighting difference is introduced. Both variants use the same equal-episode reported evaluation. Do not relabel the old selection, replace original checkpoints, or claim that matching-window inference separates training-horizon changes from the matching selection-horizon change.

For each mode, evidence that matched h10 training improves long-horizon forecasting requires a negative upper bound of the paired 95% interval for new-minus-original **mean-all-ten** error. Separately report whether ShiftWM (ours) improves over equally h10-trained Framewise, using the same metric and rule. If an interval includes zero, the result is inconclusive; positive differences indicate regressions. Retain all endpoint errors, h5 effects, and other modes without selecting only beneficial rows. These are exploratory validation results with unadjusted intervals, not independent test confirmation. No test run, tuning choice, architecture promotion or public superiority claim is authorized by this control alone.
