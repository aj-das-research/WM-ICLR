# Paired primary-planning reporting protocol

The reporter `scripts/summarize_paired_planning.py` compares factorized minus framewise calibration, shared context (`single`), and factorized without paired observation supervision (`factorized_unpaired`). It does not select a method, checkpoint, or analysis population from test performance. The trained methods and evaluation grid already exist; this reporting implementation adds paired uncertainty and explicit availability while the fixed campaign finishes. These contrasts are exploratory, not a retrospectively preregistered significance analysis.

Each environment has two populations: the held-out appearance2/dynamics2 composition, extracted from the full test file, and the pooled three prescribed extrapolation conditions `(o3,d0)`, `(o0,d3)`, `(o3,d3)`. Report raw success and success conditional on being unsolved during paid support acquisition separately. Excluding support-only successes is determined by the common recorded support rollout, before any evaluated policy acts. All three training seeds 0/1/2 must have completed evaluations for both methods in a comparison and population. Until then the complete contrast, its per-seed counts, SD, and interval remain null; availability is shown without inserting zeros or partial means.

## Source and task gates

Before a file contributes, the reporter verifies the current immutable manifest and evaluator SHA256, the checkpoint SHA256 against the completed run's `best/model.pt`, the actual run's method and training seed, the full unique validation history, and the reported checkpoint epoch against validation-best epochs. It checks completed training, saved run-configuration linkage, pretrained environment, action-statistics checksum, and consistent action/latent coordinate metadata. A checkpoint digest cannot be reused for different trained runs. Digests are cached by resolved path, size and nanosecond modification time. Weights are hashed, never unpickled; the reporter performs no model inference.

The reporter imports the strict main planning validator from `scripts/aggregate_results.py`: 300 CEM candidates, 30 iterations, 30 elites, five grouped-action horizon, 50 native interactions including up to ten support interactions, five native controls per group, one group executed per replan, checkpoint-training action z-score search with native clipping, and RNG1701. Both the hashed protocol and its derived planner metadata must agree. Random/replay, development, hybrid and future revision outputs are excluded by fixed source paths and identities.

The complete record population must exactly match the manifest's first 64 unique test initial-state seeds per relevant dynamics factor: all nine seen-factor combinations in a test file (576 tasks), or all three prescribed extrapolation combinations (192 tasks). Manifest seed sets must agree across dynamics factors. No duplicate, missing, substituted or relabelled task is accepted. Success flags are binary and internally consistent. Interrupted files validate their source, hashed protocol and every available row, while remaining pending; a legitimately absent partial planner summary is allowed, but malformed present metadata is rejected.

Across every available method and training seed, the reporter checks trajectory/appearance keys, manifest seed/dynamics identities, goal index7, support-success and policy-eligibility masks, initial full-state diagnostic distance and all recorded task-specific initial error diagnostics. Floating-point diagnostics must agree within `rtol=1e-9, atol=1e-8`. **This verifies the recorded task/support diagnostics, not unlogged pixels or full simulator states.** The main evaluator did not log support/goal pixel hashes or full-state hashes; those identities cannot be retrospectively proven from episode rows. The immutable evaluator and manifest document how the shared task/support protocol was constructed.

## Paired estimates and intervals

For each training seed, recompute binary paired outcomes from episode records. Report factorized wins, comparator wins (losses), both-success and neither-success counts, the paired success difference in percentage points, and its denominator. Across the three fixed training seeds, report the arithmetic mean difference and sample SD (`ddof=1`). Negative differences remain negative. Saved summary success rates are not used.

The percentile 95% bootstrap interval resamples **initial-state seed clusters**, with all selected appearance/dynamics conditions and all three training-seed outcomes kept together in each draw. This preserves both cross-condition and cross-model dependence. Use 20,000 draws from NumPy RNG1701. Each bootstrap estimate is total resampled paired-success difference divided by the resampled paired-task count. For eligible success, clusters with no eligible task contribute no observations and are omitted; any retained cluster keeps all of its eligible conditions. No eligible observations yields a pending cell with an explicit reason.

The interval is conditional on these three observed training seeds. It is not a confidence interval for a population of future training runs; the three-seed SD is reported separately. Contrasts are exploratory and are not multiplicity-adjusted. A degenerate zero-width interval does not establish equivalence, especially when both policies fail throughout. No result is described as a causal effect of architecture alone or generalized beyond these environments and task populations.

## Artifacts and verification

After fixture tests pass, run `.venv/bin/python scripts/summarize_paired_planning.py`. It atomically replaces `reports/evidence/paired_planning_results.json` and `paper/generated/paired_planning.tex`; it does not change evaluation files or launch jobs. The JSON records source-file checksums, training-source checksums, manifest/evaluator identities, protocol, availability and the full per-seed paired counts. The TeX shows dashes for pending contrasts and states the conditional uncertainty limitations. Parent orchestration owns any watcher/paper integration.

`tests/test_paired_planning_reporting.py` checks incomplete-seed suppression, interrupted-file handling, exact manifest populations, source/checkpoint/validation-best linkage, duplicate-checkpoint rejection, budget/search spoofing, cross-seed support equality, independent known mean and sample-SD calculations, retained negative contrasts, and a bootstrap fixture with perfectly correlated conditions and training seeds. The latter independently resamples four initial-state clusters and would detect treating the 36 task/model observations as independent.

Implementation verification on 2026-09-18: all 32 fixture tests passed. An independent read-only review by the model agent found no blocker in the clustered bootstrap, completion gates or source linkage. The first actual report validated 11 applicable source files and left all 24 contrasts pending. A temporary, explicitly synthetic fully populated table also compiled with the official ICLR2027 style at 5.5-inch text width, exercising signed three-digit estimates/SDs and full-range intervals in both numeric columns. It produced no overfull-box warnings or visible collisions. Synthetic values were confined to `/tmp/paired-planning-layout-bfwzrpcg/`; no synthetic value entered the generated evidence or paper table.
