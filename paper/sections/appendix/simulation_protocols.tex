\section{Complete experimental protocol}
\label{sec:protocol-details}
\paragraph{Environments and splits.}
The core tasks are visual PushT and Reacher in \texttt{stable-worldmodel}.
They have different control geometries but share infrastructure. Initial
observation factors are canonical, warm, and cool pointwise RGB transforms.
PushT changes space damping (0, 0.15, 0.65); Reacher changes arm and finger
density together (1000, 650, 1350 in simulator units). We train on seven
combinations, reserve $(v_1,p_1)$ for development, and hold out $(v_2,p_2)$
for the main compositional test (Figure~\ref{fig:split}). Test trajectories
are independent across the full grid. Additional dim and physical conditions
test extrapolation separately: dim appearance $v_3$, PushT damping 0.95,
and Reacher density 1500, evaluated at $(v_3,p_0),(v_0,p_3),(v_3,p_3)$.
Each environment has 256 training, 32 validation, 32 development, and 64 test
initial-state seeds. Three physical conditions in the first three splits and
four in test produce 1,216 physical episodes per environment, each with
64 grouped transitions. Appearance versions reuse those physical trajectories.
The full test planning grid has $64\times9=576$ tasks per checkpoint;
the separate extrapolation grid has $64\times3=192$. The all-condition test
average includes familiar factor pairs and is not a wholly unseen-composition
score. This controlled extension is not a reproduction of the original paper's
success table.

\subsection{Planning, eligibility, and resource measurement}
\paragraph{Primary outcomes and uncertainty.}
Closed-loop success under each environment's declared criterion is primary.
We also report steps to goal and worst-condition success under fixed budgets.
Methods use matched initial-state/goal IDs. Core comparisons target three
training seeds; actual seed and episode counts accompany each result.
Episode-level outcomes support paired comparisons; uncertainty over tasks
and variability over training seeds are reported separately. Correlated
frames are not independent trials. Failed runs and timeouts remain in the
record, with a stated policy for their inclusion in denominators.
The main planner uses 300 candidates, 30 CEM iterations, and 30 elites,
matching the released LeWM CEM sampling configuration. This budget is
locked for all model comparisons before full-test learned-policy planning.
It evaluates 9,000 candidate sequences per replan, versus 640 in the
earlier development-only setting; this $14.0625\times$ count ratio is not
a measured wall-time ratio. Both settings use
five grouped actions of prediction horizon, and one group executed per replan.
A group contains five native controls. The 50-step native budget includes
ten steps acquiring initial support. CEM optimizes in the checkpoint's
training action z-score coordinates; it converts candidates to native controls
and clips only physical bounds $[-1,1]$. It does not clip z-scores to that
range. PushT uses the relative-displacement interface from the official
training archive; the earlier absolute-control corpus is quarantined.
Success during support is recorded
separately; policy-eligible success excludes tasks already solved by that
common history. Final-state success is also retained. Per-replan latency
divides actual solve time by actual replanning calls, excluding nonexistent
calls on already-solved tasks. These are configuration facts, not measured costs.
Main efficiency results additionally require dedicated execution with no
concurrent training on the measured GPU; shared-GPU development timing is
retained in raw records but excluded from efficiency tables.

\subsection{Additional diagnostics and task scope}
\paragraph{Diagnostics.}
Completed forecast evaluations measure recursive error in frozen reference
coordinates. Action shuffling, context replacement/removal, and support-length
dependence are additional mechanism tests; their outcomes are not yet reported.
A low one-step error can arise from ignoring actions on predictable
trajectories; action interventions and planning test that failure.
Prediction diagnostics therefore include persistence, zero-action rollouts,
and the change induced by actions. Zero-action predictions are compared
with recorded-action targets only as a sensitivity check, not as errors
against observed counterfactual trajectories. PushT additionally reports a prespecified
subset requiring block translation beyond 20 pixels or rotation beyond
$\pi/9$, so tasks solved by moving the agent alone do not hide manipulation
failures. Both the full set and this subset remain visible.
Within-episode switches are a secondary evaluation after stationary
conditions. Test combinations are never used for hyperparameter selection.

Action-conditioned phantom endoscopy is an optional offline extension, outside
the minimum control claim. Forecasting alone cannot demonstrate navigation or
clinical benefit. Static diagnostic images do not provide the executed actions
required by this study.

\section{Implementation and training details}
\label{sec:implementation}
\subsection{Architecture and parameter accounting}
The initial implementation freezes a pretrained LeWM visual encoder and
projector, denoted $E_0$. Context networks, adapters, action encoder,
predictor, and prediction projector are trained. Full visual fine-tuning is
a distinct configuration. The frozen path permits feature caching without
changing inputs or targets. Equations~\ref{eq:obs}--\ref{eq:cost} specify this
historical computation.
The upstream architecture contains 18,034,478 parameters. The ShiftWM
\emph{active inference path} uses 18,319,598, with 12,025,454 trainable
offline. Shared context has 12,025,046 trainable parameters.
The current loaded model object contains 24,873,110 parameters including
the duplicated frozen reference encoder and inactive ablation modules;
the current package serializes that full state. Active-path counts are
not claims about package size or runtime memory, which must be measured
on the actual released artifact.

For $d=192$ and $H=L=3$, both contexts have width 32; the dynamics network
uses a 128-unit GRU. The observation network pools support-feature mean and
population variance. Both adapters use bounded-scale residual FiLM. Inference
holds contexts fixed within a search, so imagined futures cannot modify the
information used to infer dynamics.

Framewise calibration uses the per-image residual
$u+\mathrm{MLP}(\mathrm{LN}(u))$ with dimensions $192\to128\to192$
and an initially zero output layer. It corrects history and goal images
identically, receives no temporal context, and uses the prediction and
canonical-alignment losses. It adds 49,856 active parameters; its active
path has 18,084,334 parameters, of which 11,790,190 are trained offline.
Shared context matches the context-network parameter count approximately;
architecture attribution must still account for computation differences.

\subsection{Exact losses and temporal indexing}
\label{sec:loss-details}
Let $o_t^*=R_{v_0}(x_t)$ be a paired canonical training render and
$z_t^*=\sg(E_0(o_t^*))$ its frozen target. For a sequence indexed $0,\ldots,T-1$, context uses only indices
$0,\ldots,H-1$. Define $\mathcal T_{\mathrm{pred}}=\{H,\ldots,T-2\}$
and $\mathcal T_{\mathrm{align}}=\{H,\ldots,T-1\}$. The implemented query losses are
\begin{align}
 \mathcal L_{\mathrm{pred}}&=\frac{1}{|\mathcal T_{\mathrm{pred}}|}\sum_{t\in\mathcal T_{\mathrm{pred}}}
 \operatorname{mse}(\hat z_{t+1},z_{t+1}^*),\label{eq:predloss}\\
 \mathcal L_{\mathrm{align}}&=\frac{1}{|\mathcal T_{\mathrm{align}}|}\sum_{t\in\mathcal T_{\mathrm{align}}}
 \operatorname{mse}(z_t,z_t^*).\label{eq:alignloss}
\end{align}
Here $\operatorname{mse}(u,v)=\norm{u-v}_2^2/\dim(u)$ averages over
feature dimensions, matching the implementation and stated loss weights.
Training uses teacher-forced one-step query prediction. With $T=8$ and $H=3$,
context sees frames 0--2, alignment supervises frames 3--7, and prediction
supervises targets 4--7 from observed history windows. Frame 3 is not a
prediction target in this campaign. Evaluation instead starts immediately
after support and recursively predicts frames 3--7. This boundary and
teacher-forcing mismatch can affect planning even when validation prediction
error is low; the completed runs are not multi-step rollout training.
Frozen targets prevent an encoder from lowering the reported
loss solely by shrinking or changing its coordinates; they do not guarantee
that those coordinates retain every necessary physical quantity.

Appearance variants $S^{(v,p)}$ and $S^{(v',p)}$ of the same trajectory give
\begin{equation}
 \mathcal L_d=\E\operatorname{mse}(C_d(S^{(v,p)}),C_d(S^{(v',p)})),
 \label{eq:dyncons}
\end{equation}
where $C_d(S)$ abbreviates the corrected-support pathway. Distinct batch
examples with the same observation label give the regularizer
\begin{equation}
 \mathcal L_o=\E_{v,p,p',S,S'}
 \operatorname{mse}(C_o(S^{(v,p)}),C_o(S'^{(v,p')})).
 \label{eq:obscons}
\end{equation}
The implementation averages over off-diagonal batch pairs with matching
appearance IDs; it does not require their dynamics values or trajectory IDs
to differ. Grouping establishes a shared transformation, not a shared state.
The term does not force state latents of different trajectories to agree. The objective is
\begin{equation}
 \mathcal L=\mathcal L_{\mathrm{pred}}
 +\lambda_{\mathrm{align}}\mathcal L_{\mathrm{align}}
 +\lambda_d\mathcal L_d+\lambda_o\mathcal L_o.
 \label{eq:loss-complete}
\end{equation}
The initial configuration uses $\lambda_{\mathrm{align}}=1$,
$\lambda_d=0.1$, and $\lambda_o=0.01$; unpaired controls disable both context
consistency terms. No additional SIGReg term is used because the target
coordinates are frozen. These choices are configuration facts, not tuned results.
Raw context consistency also has a scale ambiguity: shrinking a context
and increasing downstream sensitivity can lower its penalty without
improving factor separation. Consistency can collapse contexts to constants. Constant-context,
context-shuffle, and removed-pathway controls therefore test whether both
contexts carry useful information. Context swapping across trajectories
is not part of the initial implementation: it requires valid matching targets.

\subsection{Training and checkpoint selection}
The reported campaign uses the fixed encoder and feature-cache path, with
RGB inputs in $[0,1]$, ImageNet channel normalization applied once, and
antialiased bilinear resizing to the released encoder input size. The visual
projector and prediction projector retain pretrained BatchNorm running
statistics. The prediction projector's affine parameters remain trainable;
freezing running statistics prevents query-frame batch statistics from
entering support features and permits batch-size-one planning.
The full campaign trains five variants (Unaligned predictor, Framewise
calibration, Shared context, Unpaired contexts, and ShiftWM), three seeds,
and two environments:
30 runs of 30 epochs,
batch size 128, stride one, and initial learning rate $5\times10^{-5}$.
All 30 configured runs have completed their 30 epochs; the generated ledger
below records the completion evidence. AdamW uses weight decay $10^{-3}$,
gradient clipping at norm 1, and a cosine schedule ending at $10^{-6}$.
Training and validation use BF16 autocast when supported; evaluation uses
FP32. Checkpoints are selected by ordinary-validation prediction MSE, not
last-epoch loss or total loss, whose alignment and consistency terms differ
across controls. Full training completion is distinct from selecting an early
validation-best checkpoint. Main planning evaluation remains separate.

Both training and CEM retain the released-data action normalization. In the
new PushT training corpus, the per-coordinate native-action standard deviations
are approximately 0.504 and 0.504, versus 0.208 and 0.207 in the released archive
(245,760 collected training actions). This distribution difference is retained
in the protocol, not retrospectively removed by renormalizing the completed
campaign. Reacher's corresponding collected and released deviations are both
approximately 0.577. These statistics describe action distributions; they do
not establish that normalization explains the planning failures.

\FloatBarrier
\section{Information access and correctness}
The support must precede query targets. No paired variant of an underlying
trajectory can cross a split. Batch grouping can use factor IDs but model
inputs cannot. Goal images convey target states, not hidden future
trajectories. Future realized actions and rewards cannot enter context
used to select an earlier action.

Checks must establish that saved models reload identically in evaluation
mode; removing adapters recovers the specified base computation; prediction
responds to action changes; support cannot replace query inputs; cached
features match online features under identical transforms; checkpoint
resumes preserve optimizer/scheduler and random state; and paired rendering
does not mutate physical state. These are correctness requirements,
not replacements for training and closed-loop evaluation.

\paragraph{What is not identifiable.}
For $x_{t+1}=x_t+p a_t$, $o_t=v x_t$, and $x_0=0$, observations depend on
the product $vp$. For every $q>0$, $(v,p)$ and $(qv,p/q)$ generate the same
observations under every action sequence. Separate physical interpretation
therefore needs additional assumptions or information. Our contexts are
functional prediction variables, not identified friction or camera
parameters. This elementary example is a limitation, not a theoretical novelty claim.

\section{Statistics and reporting}
Every episode records training seed, condition, initial-state and goal IDs,
success, length, and failure reason. A paired bootstrap resamples independent
task IDs while retaining method pairing; training-seed dispersion is
reported separately. The final interval level, calculation, resample count,
and actual sample counts accompany each completed figure. Frame count
must not inflate the number of independent trials.

The reported campaign fixes support length, loss weights, and planning
settings in its versioned configurations; no hyperparameter search over these
choices is claimed. Ordinary validation prediction error selects checkpoints.
Development diagnostics inform separately labeled follow-up hypotheses.
Framewise calibration and Unpaired contexts were added after an implementation/validation
audit, before the main learned-policy test campaign; the original runs remain
unchanged. Test evaluation follows the frozen protocol. A documented implementation
error can trigger a complete matched rerun; disappointing performance
cannot be relabeled as an installation failure. Aborted and numerically
unstable runs remain in the audit trail.

\subsection{An elementary cost-error decomposition}
This calculation explains why prediction and goal calibration require separate
checks; it is not a theoretical novelty or an empirical guarantee.
For a nonempty finite set of candidate action sequences $\mathcal A$ containing
the returned sequence, let $y(a)$ and $g$ be canonical terminal and goal latents,
and let $\hat y(a),\hat g$ be their model estimates. Define
$\|u\|_d=\|u\|_2/\sqrt d$, so squared normalized norm equals the implemented MSE.
Suppose, uniformly over $\mathcal A$,
\[
 \|\hat y(a)-y(a)\|_d\le e_f,\qquad
 \|\hat g-g\|_d\le e_g,\qquad \|y(a)-g\|_d\le R.
\]
Writing $c(a)=\|y(a)-g\|_d^2$, $\hat c(a)=\|\hat y(a)-\hat g\|_d^2$
and $\varepsilon=e_f+e_g$, expansion of the squared norm gives
\[
 |\hat c(a)-c(a)|\le 2R\varepsilon+\varepsilon^2=:B.
\]
If a returned action sequence satisfies
$\hat c(\hat a)\le\min_{a\in\mathcal A}\hat c(a)+\eta$, then
\[
 c(\hat a)-\min_{a\in\mathcal A}c(a)
 \le 2B+\eta=4R\varepsilon+2\varepsilon^2+\eta.
\]
Indeed, for a true minimizer $a^\star$, apply the cost-error bound twice:
$c(\hat a)\le\hat c(\hat a)+B\le\hat c(a^\star)+\eta+B
\le c(a^\star)+2B+\eta$.
An illustrative scalar counterexample has exact predictions $y(a)=0,y(b)=1$,
true goal $g=0$ and estimated goal $\hat g=1$: goal error alone reverses
the two candidates' ranking. This is a mathematical example, not a measured
simulator result. Empirical mean prediction MSE does not provide the assumed
uniform norm bound; CEM does not certify $\eta$. The statement concerns latent
cost on the stated candidate set, not physical success or causal attribution
for the observed failures.

\subsection{Random actions and privileged replay}
\label{sec:planning-controls}
These controls retain the same task identities, goal definition, paid support,
and native interaction budget. Random actions sample uniformly within the
native bounds using a single fixed RNG rule; they are not estimates over
three trained checkpoints or multiple independent policy seeds. ShiftWM's
three-seed raw PushT success means are 2.60\% on held-out composition and
6.77\% on extrapolation, compared with random-action point estimates of
7.81\% and 9.38\%. On Reacher the corresponding ShiftWM means are 40.63\%
and 19.62\%, compared with 4.69\% for the random control on each population.
These are descriptive comparisons; no significance or policy-seed uncertainty
claim is inferred from their ordering.

Privileged replay uses the recorded future actions that generated each target.
Its complete success verifies reachability under this replay protocol, not
fair learned-policy performance or correctness of every learned planning
operation. Neither control selects actions from world-model predictions, so
CEM settings in their common evaluator metadata do not describe a search
performed by those policies. Both raw and support-excluded eligible counts
