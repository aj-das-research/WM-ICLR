\section{Experiment alignment and single-observation transfer}
\label{app:experiment-alignment}
The current proposed method is ShiftWM's bounded observation-anchored spatial
decoder. The DROID development study evaluates its three-observation instantiation. The historical
context model and the single-observation transfer study have different
interfaces and selection protocols; their scores must not be pooled into one
cross-domain superiority claim.

\paragraph{Single-observation transfer contract.}
The IWS interface takes one observed image and $H$ recorded native
command rows, then predicts the $H-1$ subsequent stored-frame features.
For $H=60$, the observed index is $s$, the target is $s+59$, and all command
rows $s,\ldots,s+59$ condition the endpoint. These are stored indices, not
verified seconds or sixty physical transitions. The three temporal slots
initially repeat the one observed feature grid; they do not represent three
observed frames. Support-transition context and FiLM are disabled because
one image supplies no observed transition.

The study grid specifies separate per-task checkpoints for autoregression,
additive anchoring and bounded spatial mixing, with three seeds each;
persistence requires no training. PushT, Box and Rope retain their native
command widths of 4, 14 and 8. Internal splits contain 480/120, 481/121 and
481/121 training/development trajectories, respectively. Task-specific
training-only statistics and the full-RGB DINOv2 feature representation are
shared between arms within each task. This is a transfer of the decoder
mechanism, not a shared cross-embodiment checkpoint or an RLA-WM reproduction.

\paragraph{Selection, primary comparison and reserved evaluation.}
The full-horizon recipe trains all 59 offsets and selects checkpoints
by internal-development equal-trajectory endpoint MSE at $H=60$.
The declared primary comparison is bounded mixing versus the additive anchor,
with task-specific standardized feature-MSE reductions and an equal-task
macro of those reductions. Autoregression, persistence, shorter endpoints
and other feature metrics are secondary. The upstream reserved set contains
200 handles from ten trajectories per task; a handle is not an independent
trajectory. Original and derived prefix endpoints remain separately labeled.
The reserved protocol fixes all 36 development-selected checkpoints before
payload access, retaining the original comparison and treating the nine
no-$\tanh$ models as a secondary component family. It uses the exact original
handle order, not the development window stride. The three tasks contain
5,996 native frames in total. Frozen DINOv2 extraction and training-only
normalization are shared by all arms; no statistics are refitted on the
reserved recordings.

For each task, we first average handle errors within each of ten trajectories,
then weight trajectories and three training seeds equally. We also retain
the equal-handle means because handle counts differ between trajectories.
Paired 95\% intervals use 10,000 seed--trajectory bootstrap draws; shared
seed draws preserve pairing across tasks for the macro result.
All 59 full-horizon outputs remain in the ledger. Separate $H=15,30,45$
calls receive only their declared command prefixes, with CPU FP32 prefix
consistency checked at relative tolerance $10^{-5}$ and absolute tolerance
$2\times10^{-5}$. These prefix scores are stored separately, rather than
replacing the full-horizon curves. A complete 36-run finalizer checks the
primitive scores, identical persistence controls and matched input hashes
before any reserved result is reported. No checkpoint, seed or comparator is
chosen from the reserved outcomes.

\paragraph{Reusable IWS predictors.}
The 27 original predictors and nine unbounded ablations have separate
inference-only bundles containing their exact
weights, task-specific statistics and frozen model code. A relocated, offline
CPU process reproduces every forecast offset exactly on a fixed training input
for each task. This checks portability, not additional forecasting accuracy.
Inputs are one raw 6,144-dimensional DINOv2 feature vector and native commands;
outputs are future feature vectors. The local packages exclude optimizer
state, encoder weights, RGB decoders and future-target inputs. Their complete
manifests and export instructions accompany the source release; checkpoint
uploads remain separate. CPU parity does not certify the CUDA backend.

\paragraph{Result ingestion boundary.}
Only the complete 27-run finalizer can populate the original study's numerical cells. It verifies
the full training budget, checkpoint and source identities, every eligible
window and independently reconstructed metrics. Development and reserved
evaluation use distinct finalizers. Negative and inconclusive results remain
visible; incomplete studies remain pending. The separate innovation-bound
ablation requires all nine new runs and all 27 frozen original runs to pass
its own finalizer before its tables and extended forecast curves are populated.

\paragraph{Measured predictor cost.}
Table~\ref{tab:iws-predictor-resources} adds a separate, completed resource
study of all 36 released local predictors and persistence on fixed training
inputs. Each call returns all 59 forecast offsets. Across tasks, the no-$\tanh$
ablation uses 0.870--0.872 million parameters and takes about 115--116\,ms on
the profiled CPU or 64--65\,ms on the GPU, using the median of three
seed-level medians. Both spatial variants are faster than autoregression in
this measured setting; the additive anchor is faster still. This is a cost
comparison of the exported predictors, excluding the image encoder and
control loop. It supplies no new accuracy result or CUDA equivalence claim.
