# Verified observation, command, prediction and evaluation contract

The figure explains the historical registered real-video study in `paper/sections/real_video_study.tex`, using existing DROID recordings. Its visual example comes from the study's actual 132-episode held-out population, replacing the old separate DROID-100 ingestion example. It is not a newly evaluated case or an accuracy comparison.

- **Observed input:** external camera 1 frames 0, 5 and 10. Full images are resized to 224×224 by bilinear antialiasing and ImageNet-normalized for frozen DINOv2-small. Its 16×16 patch grid is mean-pooled into 2×2 spatial cells, 384 channels per cell, flattened channel-major to 1,536 features. Feature and action mean/sample-standard-deviation statistics are fitted on training camera 1 only and remain fixed.
- **Recorded commands:** one native command has six commanded Cartesian-position/pose components plus one gripper-position component; it is not a torque or velocity action. Native actions 0–4 join frames 0→5 and 5–9 join 5→10. Query blocks contain actions 10–14, 15–19, 20–24, 25–29 and 30–34, joining targets 15, 20, 25, 30 and 35. Five 7D commands concatenate chronologically into one 35D vector. Native frame numbers are not calibrated time.
- **Historical predictor:** the learned width-192, four-block LeWM causal predictor receives a rolling three-feature history with recorded action blocks. The context variant infers observation context from the three encoded support features' mean/variance, and dynamics context from corrected support transitions and their two past action blocks. These original support contexts remain fixed during the forecast. Each predicted feature recursively enters the next three-feature history. Query images never enter prediction; the model emits feature vectors, not RGB images. No paired canonical or simulator factor-identification losses apply here.
- **Training versus inference:** five-query MSE training uses recorded future features as supervised targets. The setup illustration's inference boundary separates these evaluator-only future images from model-visible support and commands; it does not claim targets were excluded from the training loss. The 12 runs comprised four modes × three seeds, each 30 epochs, selected on complete validation forecast loss.
- **Scoring:** the registered primary evaluation reports h=1,3,5 action-block endpoints, at frames 15,25,35 for this first window. h=10/frame60 is a separate extrapolation test. Raw MSE, train-standardized MSE and cosine error compare predicted features with frozen features of the recorded future. Evaluation stride is five stored frames (25 native transitions). Window errors are averaged within episodes, then episodes equally; paired uncertainty resamples sessions and training seeds. No closed-loop robot success is measured.
- **Other views:** external camera 2 uses the same held-out episodes in a separate camera-transfer pass. It is excluded from training, normalization and checkpoint selection and is not fused with camera 1. The processed wrist stream is preserved for inspection only; it has no model feature cache.
- **Current method is different:** the main spatial method pools 4×4×384=6,144 features, uses width 96 and fixed observed-source spatial transport plus bounded innovation. It is not this historical recursive 2×2 context decoder. Its original-development evidence must not be attached to this held-out setup example.

The packet contains no predicted feature values, generated future RGB, new model inference or new performance metrics. Any drawn 2×2 feature tiles must be labeled schematic and their colors must not purport to encode measured feature values. Do not route the future target, alternate camera or wrist into the primary model.
