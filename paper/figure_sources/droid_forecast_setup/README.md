# Recorded DROID forecasting setup (Figure 7)

Run `.venv/bin/python paper/scripts/render_droid_forecast_setup.py` from repository root. Only this portable pack and Matplotlib/NumPy/Pillow are needed. The same canonical point-coordinate scene writes publication PDF, editable SVG, PNG previews and native `.drawio`; no model, encoder or private dataset is required to redraw it.

The photos are exact source-study observations from episode `droid-003c304c89aa9c7bea5656bc`, the lexicographically first original-test episode supporting an eight-frame window. Selection is independent of model output or success. Input observations are native0/5/10, and the illustrated target35 is the fifth future block after10. Each action block contains five7D recorded commands. The full packet retains both external streams at0/5/10/15/25/35 plus the wrist view at10, seven complete command blocks, source hashes and selection order.

The left cartoon is an original schematic of camera roles; camera positions and angles are not measured extrinsics. PrimaryCamera1 supplies train/validation/test; Camera2 evaluates separate held-out viewpoint transfer. Wrist images are inspection-only. There is one camera stream per model run. The unmodified full RGB observations, including publisher blurring, remain raster; all added geometry, labels, feature symbols and connectors are editable. The2x2 tiles are schematic1536D pooled features, not measured outputs or RGB forecasts. This plate describes the historical context-model study, not the current4x4 spatial architecture.

The predictor receives only observed support and logged commands. The withheld future photo reaches only the evaluator. Encoder boxes share the frozen DINOv2-small weights and training-camera1 feature-statistic convention. Reported errors include raw/standardized featureMSE and cosine error as defined in the manuscript; exact protocol and information exclusions are retained in data.json. Five future vectors are forecast recursively without query-image teacher forcing; only the fifth is drawn. No gradients, robot-control execution, new forecast results or performance gains are implied.

DROID photos are CC BY4.0; see LICENSE-DROID.txt and data.json source bindings. Source images were not cropped, recolored or generated. The original DROID-100 inspection grid remains archived at paper/generated/real_video/recorded_droid_views.*. This figure replaces its role in the manuscript with a complete task explanation.

Three composition alternatives were rendered and inspected. The chosen camera-vignette / input-lane / evaluator-lane layout preserves a wide reading order and8pt minimum labels at5.5in manuscript width. See brief.md for decisions. The native file is generated from the same ordered geometry; application-rendered verification is recorded separately under reports/evidence/droid_forecast_setup_native_review.json.
